# I Ching PWA — v4.1 interpretation model

## Core reading model

The application reads a casting as a three-stage process:

**Поточний стан → Точки зміни → Напрямок розвитку**

1. **Початкова гексаграма — СТАН**  
   Відповідає на питання: «У якій ситуації я перебуваю?»

2. **Змінна лінія — ЗМІНА**  
   Відповідає на питання: «Що саме в цій ситуації зараз рухається або потребує уваги?»  
   Кожна змінна лінія має індивідуальні `title`, `stage`, `meaning`, `advice`.

3. **Результуюча гексаграма — НАПРЯМОК**  
   Відповідає на питання: «Яку нову якість набуває ситуація через цю зміну?»  
   Вона не є гарантованою «нагородою» за виконання поради, а показує новий стан / перспективу розвитку, що формується зміною активних ліній.

Якщо змінних ліній кілька, вони описують кілька активних точок одного поточного стану, а всі їхні зміни разом формують одну результуючу гексаграму.

Якщо змінних ліній немає, читання залишається на рівні початкової гексаграми; штучно створювати результуючу гексаграму не потрібно.

## Hexagram cycle

`hexagrams.js` отримує поле `cycle`: коротку карту внутрішнього розвитку шести позицій гексаграми. `cycle` не є додатковою або «сьомою» стадією і не замінює результуючу гексаграму.

Приклад для №2 Кунь:

**помітити → узгодитися → виконати → стриматися → стати опорою → не перейти межу**

## Changing lines

`changing-lines.js` має перейти від універсальних назв на кшталт `Лінія N — ...` до індивідуальних описів кожної лінії.

Структура:

```js
{
  title: "Не форсувати початок",
  stage: "Початок процесу",
  meaning: "...",
  advice: "..."
}
```

`title` — коротке практичне формулювання головного змісту лінії.  
`stage` — структурне місце в розвитку процесу.  
`meaning` — сучасне пояснення конкретної лінії.  
`advice` — практична рекомендація.

## Classical interpretations

`classical-lines.js` зберігає окремі стислі українські перекази Вільгельма і Шуцького, а не цитати.

Вони мають залишатися двома незалежними ракурсами, а не двома синонімічними перефразуваннями одного шаблону:

- **Вільгельм** — образ, життєва ситуація, морально-практичний сенс.
- **Шуцький** — структура, позиція лінії, фаза розвитку гексаграми та текстологічний контекст.

Не починати обидва трактування механічно однаковою назвою гексаграми, якщо цього не вимагає зміст.

Практичні `meaning` та `advice` не є механічним «середнім» між авторами; це сучасне прикладне прочитання, яке спирається на класичний матеріал.

## Transition interpretation

Смисловий міст не слід жорстко записувати в окрему лінію як «лінія X завжди веде до гексаграми Y», тому що при одночасній зміні кількох ліній результуюча гексаграма буде іншою.

Повне читання переходу складається з:

**початкова гексаграма + активна лінія/лінії + результуюча гексаграма**.

Майбутній рушій переходів може складати зв'язний текст із цих трьох шарів. Окремі ручні описи переходів потрібні лише там, де автоматичне складання втрачає важливий зміст.

## First v4.1 content package

Перший повноцінний пакет: гексаграми **№2–10**.

№2 і №3 використовуються як еталон стилю; після їх перевірки той самий стандарт масштабується на №4–10.

### №2 Кунь — UI titles draft

1. **Побачити перший сигнал** — Перші ознаки
2. **Не заважати правильному ходу** — Природне узгодження
3. **Дія без потреби у визнанні** — Виконання
4. **Обережна закритість** — Вихід у зовнішнє
5. **Тиха сила** — Зрілий прояв
6. **Не перетворювати підтримку на суперництво** — Межа сприйнятливості

## UI terminology

Замість технічного акценту на «додатковій гексаграмі» інтерфейс має пояснювати логіку читання:

**Поточний стан → Точки зміни → Напрямок розвитку**

Це є базовим принципом інтерпретаційної моделі v4.1.
